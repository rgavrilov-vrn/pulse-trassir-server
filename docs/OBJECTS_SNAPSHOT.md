# Инвентаризация объектов: agent.objects_snapshot

## Основание
На сервере video81 проверено: objects_list() без аргументов не поддерживается; objects_list('') вернул 204 объекта; objects_list('Server') — один сервер tkcbkSr1; Channel — 82. Формат строки: (name, guid, class, parent). Новый модуль inventory.py использует именно objects_list(''), без фиксированного списка классов.

## Включение
В локальный config.json добавьте раздел objects_snapshot из config/objects_snapshot.example.json. Этот отдельный пример автоматически не читается и не заменяет полный config.json. enabled=true, interval_seconds=300. Допустимый интервал 10..86400 секунд. Отсутствующий раздел выключает сбор. Настройки применяются динамически; ошибка сохраняет предыдущие настройки инвентаризации. Включение/изменение периода инициирует снимок при ближайшем tick. Collector.enabled=false выключает все его сборщики. Первый снимок после запуска — при первом tick.

## Обновление
Остановите Collector/Sender проверенным способом; сохраните конфиг и согласованную копию БД. Скопируйте inventory.py рядом с features.py и core.py. Замените содержимое SDK-скрипта Collector новым scripts/collector.py. Теперь он передаёт settings и objects_list в приложение. Убедитесь, что загружены новые модули и созданы новые экземпляры без прежних подписок. Не меняйте server_id и очередь. Сначала проверьте сбор с выключенным Sender. Приёмник должен поддерживать новый тип события.

## Содержание
Событие agent.objects_snapshot/event_version=1.0. Общая обёртка события и HTTP-контракт 1.0 прежние; server_id находится в HTTP-пакете. Объекты: object_id, name, class_name, parent_id. UTF-8 байтовые имена преобразуются в Unicode. Нет чтения произвольных состояний/методов/настроек, IP/пароли не выгружаются. Это полный перечень выданных SDK объектов с четырьмя полями, не полный снимок каждого живого SDK-объекта.

Data: snapshot_id, collection_started_at, collection_finished_at, snapshot_atomic=false, scope=sdk_visible, sdk_rows_count, objects_count, failed_rows_count, counts_by_class, visible_server_guids, collection_complete, collection_errors, part_index, parts_total, objects. objects_count и counts_by_class относятся ко всему снимку, не к одной части. Нумерация частей с 1. У каждой части свой event_id, у всего снимка общий snapshot_id. collection_complete обозначает успешный разбор SDK-выдачи, не факт сохранения/доставки всех частей.

## Границы и дерево
Собираются все записи SDK, не применяется фильтрация по классам. scope=sdk_visible не обещает только локальные объекты, если впоследствии подключены удалённые серверы. visible_server_guids позволяет увидеть серверные корни, но принадлежность объектов не угадывается по префиксу GUID. Родители tkcbkSr1C/tkcbkSr1I/tkcbkSr1S сохраняются как вернул SDK; наличие полной цепочки родителей в выдаче не гарантируется. Самоссылка корня Server допускается. Фиктивные узлы и связь камеры с каналом не выдумываются.

## Размер и полнота
Снимок разбивается на части по полному размеру одиночного HTTP-пакета: не более min(64 КиБ, sender.max_batch_bytes). В схеме пакета использованы текущие поля Sender; при развитии транспорта эту оценку нужно обновить. Проверяются все части до начала записи. Если один объект/метаданные не помещаются, снимок не сохраняется, причина в collector.log. Число объектов специально не ограничено. Для очень больших деревьев сбор всё ещё выполняется синхронно и может задержать callback.

Ошибка перечисления даёт collection_complete=false с ошибкой. Неправильные строки пропускаются с failed_rows_count и диагностикой первых 20 ошибок. Ошибки UTF-8 не скрываются заменой символов. Это позволяет не считать повреждённый снимок полным.

Каждая часть записывается существующим self.save отдельно. При сбое БД после части возможен неполный снимок. Приёмник должен собрать все parts_total уникальных part_index одного snapshot_id, проверить collection_complete и суммы объектов, и только затем заменять инвентарь. Неполнота, ошибка или отсутствие части НЕ означает удаление объектов. Дубликаты устраняются по server_id+event_id. Старые снимки не должны заменять более новые только из-за позднего получения последней части; порядок определяйте по collection_started_at и политике приёмника.

## Диагностика
В collector.log: Objects snapshot saved с числом объектов/частей и complete. В JSONL и SQLite ищите agent.objects_snapshot. Данные идут той же очередью и подтверждаются только HTTP 200. JSONL — best-effort, не подтверждение доставки. Существующее ограничение sqlite3.Row/Unicode в Sender этим модулем не исправляется. Приём health и снимка не доказывает получение обычных SDK-событий. README/OPERATIONS описывают базовый проект; расширения смотрите также в HEALTH_RAW.md и этом документе.
