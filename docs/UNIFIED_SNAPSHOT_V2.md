# Единый agent.objects_snapshot / event_version 2.0

## Что заменяет
Новый unified_snapshot.CollectorApplication наследует только core. Старые циклы inventory, object_health, object_states, profiles и отдельный trassir.health не запускаются. Импорт inventory используется только ради SDK-text и сериализации/разбиения; импорт features ради raw_sdk и безопасного преобразования. Heartbeat, trassir.system_event и файловые события остаются отдельными. Существующие SQLite, JSONL и HTTP contract_version=1.0 не меняются. Старые события очереди не удаляются. Старые модули остаются для отката.

## Состав
Один objects_list("") на цикл, одна запись на GUID. Общие поля objects[]: object_id, name, class_name, parent_id, observed_at, collection_complete, values, collection_errors. Нет states/metrics/health/value_types. Исходные JSON-скаляры сохраняются, строки 0/1 не становятся числами/bool, пустая строка не становится null. Snapshot-конвертер ограничивает строки/сложные значения; любые ограничения помечаются ValueLimited, полнота=false. Ошибка поля даёт values[field]=null и collection_errors с именем поля/типом исключения. SDK None даёт null без ошибки. Тексты исключений не копируются. Неизвестный класс остаётся в перечне с values={} и без обещания диагностики его работоспособности.
Channel: шесть уже проверенных полей signal/recording_local/recording_hw/fps_main/kbps_main/grabber_error из settings/channels. IP Device: connection/hdd; Script: health/check_me; Script (Local): state; Template: state/shared; Folder и FolderH: folder из object(guid).state(name). SDK object явно передан из серверного скрипта, не подменяется Python builtin object.
Server: выбранные поля settings("health") читаются в values ровно у привязанного локального Server; settings-folder health получается один раз за цикл. parent_id сохраняется как вернул SDK, включая самоссылку корня. Автопривязка допускается только при единственном видимом Server; при нескольких задайте local_server_guid. Он должен существовать среди Server текущего снимка; при неоднозначности/отсутствии — LocalServerNotResolved, без выдуманного GUID и без копирования локального health удалённым серверам. У других Server values={} (в этой версии их health не опрашивается).

## Метаданные и полнота
data: snapshot_id, part_index/parts_total, scope=sdk_visible, snapshot_atomic=false, время начала/конца, sdk_rows_count, objects_count, counts_by_class, failed_rows_count, field_errors_count, local_server_guid/visible_server_guids, requested_fields_by_class, collection_errors. requested_fields_by_class.Server относится только к local_server_guid.
inventory_complete означает полное перечисление без некорректных/дублирующихся строк; enrichment_complete — успешную привязку сервера и отсутствие ошибок выбранных значений у перечисленных объектов; collection_complete=оба признака. collection_complete объекта — успех чтения, не исправность оборудования: Needs Attention, Model Mismatch, Disabled и прочие реальные значения не превращаются в ошибки сбора. Снимок последовательный, не атомарный. observed_at объекта — завершение чтений, не время исходного события.
Все части используют общие метаданные; счётчики относятся ко всему снимку. Один объект не разрывается между частями. Полный одиночный пакет ограничен min(64 КиБ, sender.max_batch_bytes), итоговый HTTP-батч по-прежнему ограничивает Sender. Сбой записи может оставить неполный набор частей. Приёмник собирает по server_id/event_type/event_version/snapshot_id; ждёт все части. Полнота перечня и доступность значений применяются раздельно: ошибка поля не означает offline, отсутствие объекта в неполном перечне не означает удаление. При полном перечне исчезновение — только в прежней области SDK-видимости. Сохраняйте успешные значения отдельно от отметки ошибки, не выдавайте старые значения за свежие.

## Конфигурация
Фрагмент config/unified_snapshot.example.json перенесите в свой полный config.json, заменив прежний раздел objects_snapshot, не создавая дубликат ключа. enabled отсутствует = false, interval по умолчанию 60, допустимы 10..86400. Существующий interval_seconds=300 останется 300, пока вы явно не измените его. local_server_guid=null означает автопривязку при одном Server; для пилотного video81 можно явно задать подтверждённый GUID tkcbkSr1.
server_health_fields и channel_fields — непустые списки разрешённых полей без повторов. При их отсутствии используются прежние health.fields и objects_health.fields; если их тоже нет — полный allowlist server health из features и шесть Channel-полей. Полный server allowlist может содержать недоступные на конкретной сборке показатели: используйте проверенные 21 поле из примера. Разделы health.enabled, objects_health.enabled, objects_states и monitoring_profiles новым Collector не управляют и отдельных событий не создают. Их интервалы игнорируются; выбранные health.fields/objects_health.fields используются только как совместимые значения по умолчанию. Новый основной переключатель — objects_snapshot.enabled, общий — collector.enabled. raw_sdk сохраняет прежнюю функцию. Ошибочные настройки снимка/raw_sdk оставляют предыдущие рабочие настройки и логируются.

## Развёртывание
Сохраните конфиг и согласованную копию БД. Остановите прежние Collector/Sender проверенным способом; reload не отменяет подписки/таймеры, этот скрипт сам их не останавливает. Не создавайте второй Collector. Добавьте unified_snapshot.py рядом с актуальными core/features/inventory; замените содержимое серверного Collector новым scripts/collector.py. Точка входа перезагружает core -> features -> inventory -> unified_snapshot один раз перед новым app, чтобы не смешивать поколения Python 2 классов. Старые object_states/profiles/object_health для нового пути не импортируются. Sender не меняется; сохраните server_id, URL, токен, пути и БД. Схема/очередь не пересоздаются.
Сначала оставьте Sender выключенным. В collector.log должны быть Unified Collector started и Unified snapshot saved: objects=... parts=... errors=0 inventory=True complete=True. В JSONL проверяйте event_type=agent.objects_snapshot, event_version=2.0, Server.values с health и остальные классы с values. Проверяйте минимум несколько циклов с новыми snapshot_id; новые староформатные health/states события не должны продолжать появляться. Если появляются — проверьте старые обработчики.
Приёмник должен поддержать v2 и старые уже накопленные события; код приёмника этим коммитом не меняется. Отправку включайте после проверки приёмника. Проверены синтаксис Python 3 и логика collect на имитации SDK (единый перечень, health один раз, пустые значения/неизвестные классы, ошибки полей, неоднозначный/явно выбранный сервер, дубли GUID). Реальные Python 2/TRASSIR, сериализация и доставка нового объединённого пути требуют пилотной проверки. Синхронный SDK-опрос под RLock без deadline; строгий период не гарантирован. Известную проблему sqlite3.Row/Unicode в Sender это объединение не исправляет. Состав Template, связи IP Device/Channel, редкие расширенные профили и агрегаты Folder в v2 не добавлены.
