# Эксплуатация и сопровождение

## Установка без сборки
Развёртывание — копирование содержимого проекта в C:/TRASSIR_Agent. Сохраняйте src/, scripts/, config/ и docs/. Никаких tools/build.py, pip, exe и команд запуска тестов нет. Подробная последовательность и контракт — в [README](../README.md). Внутри вашей сборки TRASSIR проект ещё не проверен.

Создайте config.json из config/config.example.json и secrets/api.token отдельно. Не перезаписывайте их при обновлении. ROOT в обоих SDK-скриптах должен указывать на каталог установки на сервере. Код scripts/*.py вставляется в серверную автоматизацию, не запускается как обычная консольная программа.

## Где искать данные
- state/queue.db — события, пакеты, позиции файлов и идентичность установки.
- logs/collector.log — ошибки сбора/конфигурации/копирования в JSONL.
- logs/sender.log — результаты отправки, HTTP-статусы и типы сетевых исключений.
- archive/events.jsonl — best-effort копия событий, не история доставки.
Пути меняются через storage при остановке/перезапуске. Диагностические логи: 2 МиБ и 3 предыдущих файла; JSONL: 10 МиБ и 3 предыдущих. Ограничьте права доступа.

## Проверка очереди
Открывайте локальную БД совместимым SQLite-клиентом; не редактируйте её во время работы без плана.
```sql
SELECT status, COUNT(*) FROM events GROUP BY status;
SELECT MIN(created) FROM events WHERE status IN ('pending','batched');
SELECT id, attempts, error, next_at, lease FROM batches WHERE status='pending';
SELECT id FROM events WHERE status='quarantine';
SELECT * FROM meta;
```
Времена created/next_at/lease — Unix seconds. Pending — ещё не упакованы; batched — ждут подтверждения пакета; delivered — принят HTTP 200; quarantine — не помещаются в лимит пакета.

## Типовые ситуации
- Нет событий: проверьте серверный контекст, активность Collector, enabled, фильтры, права и collector.log. Heartbeat не доказывает получение SDK-событий.
- Нет отправки: проверьте sender.enabled, токен, CA, URL, sender.log и next_at/lease. Один пакет с ошибкой блокирует следующие.
- HTTP 401/403: исправьте токен/права; данные не удаляются. Любой не-200 повторяется.
- Config rejected: исправьте JSON/версию/диапазон; действуют предыдущие настройки. При первом запуске неверный файл не допускает запуска.
- Database identity mismatch: сервер/приёмник не соответствует БД. Не удаляйте meta для обхода; согласуйте миграцию очереди.
- File copy failed: БД уже сохранена, отправка возможна. Файловая копия этого события не повторяется.
- Event NOT saved / database is locked: событие могло потеряться. Проверьте нагрузку и блокировки, не считайте JSONL аварийной очередью.
- Quarantine: изучите размер события и лимит пакета. Возврат в очередь — только после анализа; автоматической отправки quarantine нет.

## Конфигурация и обновление
Меняйте JSON атомарной заменой. Проверка не чаще раза в 5 секунд при callback/tick. Токен читается заново при POST; не добавляйте его в код. Отключайте Sender через enabled, не удаляя очередь. При смене URL/server_id нужна миграция либо новая БД после явного решения о старых событиях.

Обновление: остановить оба скрипта проверенным способом; сохранить рабочие настройки/секреты; после закрытия соединений сделать копию SQLite; заменить только исходники и SDK-точки входа; загрузить новый код проверенной процедурой; проверить события и доставку. Простого import недостаточно из-за кеша модулей. Автоматических миграций и безопасного отката несовместимой схемы нет.

## Диск и retention
Retention применяется только к delivered, не pending/quarantine. Очистка запускается примерно раз в час при включённом Sender, удаляет до 100 старых пакетов за проход. Значение 0 отключает удаление. Резкий перевод всех данных в delivered вручную недопустим. DELETE не уменьшает файл БД; VACUUM — отдельно на остановленной установке с запасом диска. Квота очереди не реализована: мониторьте свободное место, объём и возраст.

## Файловые источники
Пути/кодировку подтверждайте на сервере. Не подключайте собственные логи агента, архив и SQLite. Чтение до 100 частей по 64 КиБ за цикл на источник, позиции фиксируются с событием. Неполная короткая строка ждёт newline. Ротация базовая: возможны пропуски при rename/copytruncate и особенностях inode Windows. Для полного охвата требуется отдельное развитие адаптера.

## Ручная проверка перед тиражированием
Проверить импорт модулей в Python 2.7.18 и SQLite 3.31.0; фактические ev.* и миллисекунды timeout; пути/ACL; реальные события; работу двух соединений; неверный конфиг; потерю сети и ответа; не-200, TLS, токен; перезапуск после POST; полный диск и ротацию. Синхронный HTTPS может задерживать Script Engine, отдельный скрипт не даёт изоляции процессов. Socket timeout не ограничивает весь DNS/запрос.
Сначала один сервер, затем малая группа, затем остальные. Пропадание heartbeat контролирует внешний сервис. Health/камеры и историческое восстановление пока не реализованы.
