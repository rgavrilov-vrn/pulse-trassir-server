# Регулярный сбор подтверждённых SDK-состояний

## Объём
Новый object_states.py оборачивает profiles. Существующие health, inventory и профили не отключаются и не заменяются. Получает SDK-функцию object четвёртым аргументом из серверного скрипта. Только чтение object(guid).state(name), без управления объектами, создания подписок или дополнительных таймеров.
Allowlist: IP Device=connection,hdd; Script=health,check_me; Script (Local)=state; Template=state,shared; Folder/FolderH=folder. Имена и фактическое чтение подтверждены пилотным логом 2026-11-09, но доступность каждого объекта проверяется при каждом опросе.

## Включение
Сохраните конфиг и согласованную копию БД. При остановленных Collector/Sender скопируйте src/trassir_agent/object_states.py рядом с актуальными profiles.py и остальными модулями. Замените серверный Collector содержимым scripts/collector.py. Импорт теперь из trassir_agent.object_states; app получает settings, objects_list и SDK object. Не запускайте второй Collector параллельно. Reload модулей сам по себе не отменяет старые подписки/таймеры; используйте проверенную процедуру остановки/перезапуска обработчиков. При обновлении зависимостей порядок core -> features -> inventory -> object_health -> profiles -> object_states, затем новый app. Sender не меняется.
Добавьте objects_states из config/objects_states.example.json в полный локальный config.json. Это фрагмент, не замена полного конфига. Отсутствие раздела означает enabled=false. В примере включены все шесть классов раз в 60 секунд. classes можно сократить до нужных классов, имена состояний фиксированы. interval_seconds=10..86400, bool не принимается как интервал. enabled/classes/interval применяются при обновлении конфигурации, ошибочный раздел сохраняет предыдущие настройки состояний. collector.enabled=false выключает всё. Не меняйте server_id, токен, URL и пути; миграции/пересоздания БД не требуется.

## Событие
Тип agent.objects_states, event_version=1.0, data.profile=sdk_states_v1. HTTP-контракт и обычная очередь/JSONL остаются прежними. Разбиение на части переиспользует inventory с измерением полного одиночного пакета. data содержит snapshot_id, part_index/parts_total, source=object.state, classes, requested_states, counts_by_class, sdk_rows_count, objects_count, failed_rows_count, state_errors_count, collection_complete/collection_errors, время начала/конца. snapshot_atomic=false: значения читаются последовательно, не являются одновременными.
В objects[]: object_id/name/class_name/parent_id, observed_at, states, collection_complete/collection_errors. Например states.connection={"value":"Connected","python_type":"str","truncated":false}. Пустая строка сохраняется, строки 0/1 не преобразуются в bool/числа. Числа/bool/null SDK сохраняются с исходным python_type; непредусмотренные типы и nonfinite float дают ошибку. Строки ограничены 4096 символами; усечение помечается ValueLimited и делает объект/снимок неполным. В лог ошибок не копируются значения/тексты исключений, только типы.
Ошибка чтения поля: states.<name>=null и collection_errors. Реальное SDK None: states.<name>={value:null,python_type:NoneType}, что отличается от ошибки. Все части создаются/проверяются до начала записи, но сбой записи может оставить неполный снимок.

## Приёмник
Для нового типа нужно разрешить agent.objects_states и хранить сырой снимок отдельно от agent.objects_health и agent.devices_snapshot. Для сборки частей используйте server_id/event_type/profile/snapshot_id. При сравнении последних снимков учитывайте data.classes: изменение выборки не доказывает удаление объектов других классов. Применяйте снимок после получения всех частей; неполные/ошибочные данные не означают offline/удаление. Состояния объектов сопоставляйте по server_id/class_name/object_id. Изменения приёмника этим коммитом не выполняются.

## Интерпретация
Нет автоматической нормализации/аварий: Needs Attention не переименовывается в Disconnected; HDD Absent не является неисправностью серверного диска; Enabled не доказывает успешность выполнения скрипта; Disabled не всегда авария. check_me, Any State, Local и пустой folder хранятся без недоказанной семантики. Не выводим active template из state и не вычисляем потомков папок. Неизвестные будущие строки сохраняются как есть. Паспорт ip_devices/900 секунд остаётся независимым от оперативного состояния/60 секунд.

## Проверка
Сначала проверьте Collector при выключенном Sender. В collector.log: Object states saved: id=... objects=... parts=... errors=... complete=.... Проверьте JSONL/SQLite: число объектов, requested_states, строки и пустые значения, ошибки. Количество может меняться из-за создания диагностических скриптов. В диагностическом снимке 15:58:15 было 82 IP Device, 2 Script, 27 Script (Local), 4 Template, 5 Folder, 1 FolderH; это пример, не зашитая норма. Диагностические скрипты можно отключить, они не нужны для регулярного сбора. Время опроса не realtime-гарантия, SDK-вызовы синхронны под общим RLock, deadline нет. Работоспособность нового регулярного пути ещё требует проверки на пилотном сервере. Известную проблему sqlite3.Row/Unicode в Sender это расширение не исправляет. Документ MONITORING_PROFILES.md описывает предыдущий этап; сведения о states здесь его дополняют, состав шаблонов/связи устройств и каналов/агрегаты папок всё ещё не реализованы.
