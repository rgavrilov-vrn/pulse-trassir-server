# Паспорт IP Device и связи с Channel

Расширение device_snapshot сохраняет единый agent.objects_snapshot/event_version=2.0 и дополняет values. Предыдущие состояния, Server health и метрики Channel сохраняются. Отдельных событий устройств нет.

## Настройки
Полный config.json для пилотного video81 теперь находится в корне репозитория. Sender выключен. URL/destination/storage/server_id/raw_sdk сохранены из предоставленного конфигурационного файла, токен не включён — только путь secrets/api.token. URL monitor.example.com оставлен как в исходном файле; это не подтверждённый рабочий адрес приёмника. Если локально уже изменили настройки, не затирайте их старой копией.
objects_snapshot.device_fields: разрешены только connection_ip, connection_port, family, model; пустой список/отсутствие отключает паспорт. Поля доступны по документированному settings/ip_cameras/<GUID>, но чтение на текущей сборке ещё надо подтвердить пилотом. family — семейство подключения/производителя; ONVIF/RTSP не доказывает бренд. IP-адреса являются чувствительными данными инвентаризации; ограничьте доступ к снимкам. Логины, пароли, приватные настройки драйвера и URL потоков не запрашиваются.
objects_snapshot.device_channel_fields: явный список источников вида channel00_guid, channel01_guid и т.д. (две цифры, не более 64 полей). В пилотном config указан ТОЛЬКО channel00_guid. Это не автоматическое обнаружение всех каналов многоканального устройства: для них настройте фактические поля, недоступные индексы не угадываются и не скрываются как нормальное отсутствие. Один список применяется ко всем IP Device; неоднородным устройствам с разным числом слотов потребуется отдельное расширение/подтверждённое перечисление полей. Отсутствие/пустой список отключает обе стороны связей.

## Данные
У IP Device values дополняется паспортом и channel_ids — отсортированными уникальными GUID из выбранных полей. Один IP Device может ссылаться на несколько каналов. Непустой GUID должен быть среди Channel текущего снимка. Пустая строка SDK означает отсутствие связи в этом выбранном слоте. Ошибка/нестроковое значение/невидимый канал -> channel_ids=null плюс collection_errors с source_field. Это не пустой список каналов.
У Channel values.ip_device_id вычисляется только по прочитанным связям. Один владелец -> GUID устройства, несколько -> null и AmbiguousDeviceLink у канала/устройств. Если чтение связей хотя бы одного устройства неполно, обратные ссылки консервативно остаются null с DeviceLinksIncomplete, чтобы не скрыть возможную неоднозначность. Если владельца нет среди выбранных слотов, null без ошибки: это означает лишь отсутствие соответствия в настроенном наборе, не доказательство отсутствия устройства вообще. По именам/порядку/parent_id связи не угадываются.
В data добавлены device_channel_fields, device_links_scope=configured_channel_fields, device_links_complete (null, если связи выключены). Этот признак описывает чтение выбранных слотов/неоднозначность, не полное покрытие всех устройств/каналов и не заменяет inventory_complete. Глобальная/пообъектная полнота и field_errors_count пересчитываются. Нельзя применять выводы об исчезновении по неполной инвентаризации. Время окончания снимка учитывает дополнительное чтение, опрос всё ещё последовательный, не атомарный.

## Установка
При остановленных прежних Collector/Sender добавьте src/trassir_agent/device_snapshot.py рядом с актуальными unified_snapshot/core/features/inventory. Замените серверный Collector содержимым scripts/collector.py, импорт теперь из device_snapshot. Однократный reload: core -> features -> inventory -> unified_snapshot -> device_snapshot; не отменяет прежние подписки/таймеры. Самостоятельно не запускайте второй Collector. config.json из корня перенесите в C:\TRASSIR_Agent\config.json, предварительно сохранив предыдущий и сверив актуальность локальных настроек. БД/очередь не пересоздавайте. Другие примеры config/ относятся к предыдущим этапам, текущий полный файл — корневой config.json.
Проверьте JSONL: паспорт у IP Device, channel_ids и ip_device_id, device_links_complete, collection_errors/field_errors_count, все части снимка. Дополнительные поля могут увеличить число частей. Sender оставьте выключенным до проверки приёмника и адреса доставки. Синтаксис Python 3 и логика паспорта/обратных связей, пропущенных полей, неоднозначных владельцев и запрета password проверены на имитации SDK. Реальные Python 2/TRASSIR и транспорт нового расширения ещё требуют пилотной проверки.
