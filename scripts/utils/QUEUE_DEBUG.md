# queue_debug.py

Добавлен пользовательский скрипт диагностики очереди с восстановленными отступами и сокращённым docstring; алгоритм сохранён. Предназначен для серверного Script Editor TRASSIR / Python 2.7, функцию timeout предоставляет TRASSIR.

Создайте отдельный диагностический серверный скрипт из queue_debug.py и запустите один экземпляр. Он не импортирует модули агента и не создаёт Collector/Sender. Читает storage.database из C:\TRASSIR_Agent\config.json, относительный путь разрешает от ROOT. Пишет C:\TRASSIR_Agent\logs\queue_debug.log независимо от storage.logs.

Первый опрос через 1 секунду, затем пауза 5 секунд после прохода. На callback создаётся отдельное SQLite-соединение, закрываемое в finally; row_factory возвращает обычный dict для Unicode-ключей Python 2.7. При отсутствии файла БД выводится предупреждение. Выполняются SELECT и PRAGMA query_only=ON, записи в таблицы не производятся. Это не открытие SQLite в файловом режиме read-only: эффективность query_only зависит от встроенной версии SQLite; проверка существования файла до connect также не является атомарной защитой от удаления файла между операциями.

Параметры в начале файла: SHOW_HEARTBEAT=False, READ_LIMIT=300, SEEN_LIMIT=3000, POLL_SECONDS=5. По умолчанию heartbeat скрыты. EVENT содержит id/status/batch_id и полный payload; HTTP_BATCH — сохранённый payload пакета Sender; QUEUE_COUNTS примерно раз в минуту показывает количество событий по статусам. Ключ защиты от повторного вывода — id/status/batch_id. Изменения статуса будут показаны, только если запись остаётся в выбранном окне последних 300 событий и состояние попало в момент опроса. Быстрые переходы могут быть пропущены. Это диагностика, не полный аудит. После перезапуска кэш seen пуст.

Один HTTP_BATCH может повторяться для нескольких событий пакета, увеличивая объём лога. Используется ротация 2 MiB и три резервных файла; одна крупная запись может превысить порог. Payload может содержать IP-адреса, имена объектов и другие чувствительные данные. Перед передачей лога проверьте содержимое и ограничьте доступ; автоматического обезличивания нет. HTTP-заголовки здесь не читаются.

Не запускайте одновременно несколько копий утилиты. Для окончания диагностики остановите её проверенным способом: скрипт сам планирует следующий timeout и не имеет собственной команды остановки. При работающем Collector/Sender возможны конкуренция чтения с записью и ошибки блокировки; они попадают в Queue inspection failed, следующий опрос планируется снова. Утилита не исправляет Sender и не меняет статус доставки событий. Выполнение в реальном окружении TRASSIR данным коммитом не проверяется.
